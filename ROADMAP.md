# Roadmap

Este roadmap descreve as principais perguntas que precisam ser respondidas antes de tratar o método como algo maduro.

## v0.1 — Base pública

- [x] Definir princípio central.
- [x] Separar intenção, implementação e comportamento conhecido.
- [x] Definir camadas de evidência.
- [x] Registrar conceito de GOLDEN.
- [x] Definir papéis entre humano, IA e repositório.
- [x] Tornar a proposta pública e aberta a críticas.

## v0.2 — Critérios objetivos

- [ ] Definir critérios de entrada e saída por etapa.
- [ ] Refinar definição de DONE.
- [ ] Definir quando validação funcional é obrigatória.
- [ ] Definir política de atualização da GOLDEN.
- [ ] Separar claramente regras do método e regras específicas de projeto.

## v0.3 — Validação cruzada

- [ ] Aplicar em projetos de naturezas diferentes.
- [ ] Registrar contraexemplos.
- [ ] Identificar práticas que não generalizam.
- [ ] Revisar o método com base em casos reais.

## v0.4 — Comparação com abordagens existentes

- [ ] Comparar com SDD.
- [ ] Comparar com TDD/BDD.
- [ ] Comparar com GitFlow e Trunk-Based Development.
- [ ] Comparar com práticas agentic/AI-assisted existentes.
- [ ] Identificar conceitos já consolidados com outros nomes.

## v0.5 — Guia de adoção

- [ ] Criar exemplo mínimo.
- [ ] Criar checklist de adoção.
- [ ] Criar anti-padrões.
- [ ] Criar exemplos de aplicação em projetos pequenos e médios.
- [ ] Criar exemplos fora de CAD/BIM.

## Perguntas abertas

1. GOLDEN deve ser obrigatório ou opcional?
2. Quais camadas de evidência são mínimas?
3. Como adaptar o método para equipes grandes?
4. Qual nível de autonomia um agente pode ter por padrão?
5. Quais ações devem sempre exigir aprovação humana?
6. Como integrar CI/CD sem transformar o método em um processo lento?
7. Como medir se o método realmente reduz regressões e retrabalho?
8. Qual nome final melhor representa o princípio central?
